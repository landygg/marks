# Languages and text

[Español](../../es/developers/i18n.md) · **English**

marks comes in Spanish (`es`) and English (`en`). Each layer has its own catalog, and no user-facing text is written in the code.

## How the language is chosen

`marks_i18n::resolve` decides, in this order:

1. The `MARKS_LOCALE` variable (`es`, `en` or `pseudo`). It is meant for development and tests.
2. The first supported language in the preference list. The region is ignored: `es-MX` is `es`.
3. English.

The preference list depends on who is asking:

- **App.** The system languages. The setting in Settings > Appearance > Language is stored in `AppleLanguages`, in the app's preferences domain, and applies when the app relaunches. This exists on macOS only.
- **CLI.** `LC_ALL`, `LC_MESSAGES` and `LANG`, then the system languages.
- **Extension.** The browser picks it. Its `default_locale` is `en`.

The frontend asks the backend through `locale_info` before mounting the interface, so both halves of the app always use the same language.

## Adding a string

### In Rust (core, `src-tauri`, CLI)

core holds no text: it returns a code.

1. **If it is an error or a message from core,** add a variant to `Msg` in `crates/core/src/msg.rs` and its translation in `impl Localize for Msg` (`crates/i18n/src/msg.rs`).
2. **If it is text of the app or the CLI,** add a variant to the right enum in `crates/i18n/src/`:
   - `AppText` and `MenuText` (`app.rs`): window, tray, menu, native dialogs and notices.
   - `CliText` (`cli.rs`): the CLI's help, errors and output.
   - `DataText` (`data.rs`): names that end up inside the data, such as the "Untagged" folder of an export.
3. Add the message, under the same identifier, to `crates/i18n/i18n/es/marks_i18n.ftl` and `crates/i18n/i18n/en/marks_i18n.ftl`.
4. Read it with `fl!(loader(), "identifier")` inside `localize`. Callers use `.localize()`.

`crates/i18n/tests/catalogs.rs` requires both catalogs to have the same identifiers, attributes and variables, every plural selector to have its `*[other]` variant, and every identifier to be used.

### In the frontend

1. Add the key to `apps/desktop/src/lib/i18n/es.ts`. Its shape defines the `Messages` type.
2. Add the same key to `en.ts`. It ends in `satisfies Messages`, so the compiler complains when something is missing or extra.
3. Read it through `t`, imported from `lib/strings`: `t.cancel`, `t.bookmarkCount(n)`.

Plurals and numbers use `plural` and `num`, from `lib/i18n/format.ts`. Components in `lib/ui` do not import `t`: they take their text as props.

`catalog.test.ts` requires the same paths in `es` and `en`, and every leaf to be used.

### In the extension

1. Add the key to `apps/extension/_locales/es/messages.json` and `apps/extension/_locales/en/messages.json`.
2. In HTML, use `data-i18n="key"`. In JS, use `t(key)`, from `i18n.js`.

The API returns error codes, not text. `client.js` turns each code into the key `error_<code>`, with dashes replaced by `_`. A new code in the API needs its key in both languages: the test `extension_translates_every_api_error` requires it.

`_locales.test.js` requires the same keys and the same placeholders in both languages.

### In the bundle

The name macOS shows for the app and for the Safari extension lives in:

- `apps/desktop/src-tauri/infoplist/{es,en}.lproj/InfoPlist.strings`
- `apps/extension/safari/{es,en}.lproj/InfoPlist.strings`

## The guards

Two tests in `scripts/check.sh` fail when a user-facing literal sits outside the catalogs:

- `crates/i18n/tests/no_user_literals.rs` checks the Rust code.
- `apps/desktop/src/i18n.guard.test.ts` checks TypeScript, Svelte, JavaScript, HTML and Swift in `apps/desktop/src`, `apps/extension` and `packages/extract/src`.

Sometimes a literal is not user-facing text but the guard takes it for one: an identifier, a format, a prompt. Mark it with a comment on the same line, or on the line of the `const`, `static` or `let` that declares it:

```rust
const BEARER_PREFIX: &str = "Bearer "; // i18n-allow: format
```

- The reason is required. `temporal` is not accepted.
- A marker that lets nothing through also fails.
- The guard prints the number of markers to stderr.

## The pseudo-locale

```sh
MARKS_LOCALE=pseudo pnpm --dir apps/desktop tauri dev
```

`pseudo` starts from English, accents every string, makes it about 35% longer and wraps it in `⟦ ⟧`. It shows two things: anything without brackets never went through a catalog, and anything that gets cut off will not survive a longer language.

## Adding a language

There is no single switch. These are the places that name `es` and `en` today:

**Rust**

- `crates/i18n/src/locale.rs`: the `Locale` enum, `tag` and the `parse` closure in `resolve`.
- `crates/i18n/src/loader.rs`: one `static` loader per language, and `loader_for`.
- `crates/i18n/i18n/<language>/marks_i18n.ftl`: the new catalog.
- `crates/i18n/src/data.rs`: `DataText::all_locales`, which lists the languages so that an import recognizes a name written in any of them.
- `crates/i18n/tests/catalogs.rs`: compares `en` with `es`.
- `apps/desktop/src-tauri/src/locale.rs`: the setting values (`system`, `es`, `en`), `setting_from_languages` and `parse_setting`.

**Frontend**

- `apps/desktop/src/lib/i18n/<language>.ts`: the new catalog, with `satisfies Messages`.
- `apps/desktop/src/lib/i18n/format.ts`: the `Locale` type.
- `apps/desktop/src/lib/i18n/index.ts`: `setLocale`.
- `apps/desktop/src/lib/features/palette/commands.ts`: `LANGUAGES`, the list behind both the Settings select and the palette.
- The `languages` and `cmdLanguage` keys of every catalog.
- `apps/desktop/src/lib/i18n/catalog.test.ts`.

**Extension**

- `apps/extension/_locales/<language>/messages.json`, with its `lang` message.
- `apps/extension/_locales.test.js`.
- `apps/desktop/src-tauri/src/api.rs`: the `extension_translates_every_api_error` test walks `es` and `en`.

**macOS bundles**

- `apps/desktop/src-tauri/Info.plist` and `apps/extension/safari/Info.plist`: `CFBundleLocalizations`.
- `apps/desktop/src-tauri/infoplist/<language>.lproj/InfoPlist.strings`, and its entry under `bundle.resources` in `tauri.conf.json`.
- `apps/extension/safari/<language>.lproj/InfoPlist.strings`. `scripts/build-appex.sh` copies every `*.lproj`.

**Documentation**

- `docs/<language>/`, with the same pages as `docs/es/` and `docs/en/`.

Nobody has added a third language yet. The list comes from searching the source for the two codes, leaving out formatting tests and fixtures; it may miss a place that only shows up when compiling or running the tests.
